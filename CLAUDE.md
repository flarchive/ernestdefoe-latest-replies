# Latest Replies: working rules

- **Commit straight to `main` and push. Never open a pull request on this repo.** Commit subjects are conventional (`feat:`, `fix:`); the release drafter bumps from the subject.
- `js/dist` is committed and is what forums load. After any change under `js/src`, run `npm run build` in `js/` (from a fresh `npm ci`) and commit the bundle; CI fails if it is stale.
- Publishing a release is Ernest's click. Nothing is announced until he says so. Every change goes to the Command Center for review first.

## Design rules that exist for a reason

- **We never query posts ourselves.** `Feed` asks Flarum's API (`/discussions` or `/posts`), through the whole API pipe: a member as themselves; 🚨 the shared guest answer as NOBODY (`StatelessApi::asNobody`: a request built from nothing, no session, cookies, headers or IP — `Client` builds from PHP's globals and `withParentRequest` copies session/IP, so one guest's Spoiler Shield reveal or a crawler's Velvet Rope pass would be cached for every guest; `the_shared_guest_answer_is_never_a_trusted_visitors_view` fails on that). Either way so every visibility scope and every other extension's redaction (Spoiler Shield, Velvet Rope, Byobu, Approval…) has already run. Our own rules only take more away: hidden and unapproved posts and hidden discussions (`Feed::shows`; a moderator's answer still has them), replies by members the viewer ignores (fof/ignore-users, absent-safe), and 🚨 private discussions and posts, never listed even to their participants or admins (Ernest's rule, fixed, not a setting): `Feed::privateIds` reads `is_private` from the rows returned (one query), so it holds whatever Byobu serializes. flarum/messages dialogs are their own tables and never reach these endpoints.
- **Excerpts are an allow-list** (`Excerpt`): only the text of p/strong/em/a/li/headings… in the contentHtml the API gave this viewer, and not even those when `hidden`, `aria-hidden`, display:none/visibility:hidden or a class with "spoiler". Spoilers, code, quotes, embeds, details and unknown elements are dropped whole. Off by default.
- **The answer is plain JSON shaped for other gates**: each row has `discussionId` + `discussionTitle`, a `/d/{id}` `url`, `slug` and `excerpt`, the keys Spoiler Shield's generic scrub looks for.
- **Caches** (all forgotten by bumping a version key on any post/discussion change, approval, tagging, Byobu recipients, any settings save, user rename/avatar/delete): guests share one answer per tag id and size for 60 s, and while one request rebuilds it (cache lock) the rest get the previous answer; each member's own answer is kept 20 s (key has the user id), so a burst of Realtime pushes costs one rebuild each. Never a cache shared by group. `?tag=` resolves to exactly one existing tag the viewer can see (exact slug) or none.
- **Rows from /api/posts** (per-post mode, and per-discussion mode for a member who ignores someone, so an ignored last reply falls back to the reply before): pages of 50, at most 4, because /api/posts has no tag filter.
- **Lean**: the API is asked with sparse fieldsets (`fields[...]`, `contentHtml` only with excerpts on), so other extensions' fields aren't computed (dev, all enabled: 66 → 48 queries per discussion list, 209 → 40 per post list). Spoiler Shield still redacts (it looks marks up when `ssMark` isn't asked for). In per-discussion mode the last post is included only when excerpts are on (every extension adds queries to a post's payload; the discussion's `lastPostNumber`/`lastPostedAt` are enough). Queries are constant in the row count (`~/github/scopes/latest-replies/measure.php`).
- **Placement counts real mounts** (`placement.ts`): stock copies (`stock-*` hosts) stand down only while a widget host (Bespoke, FoF, Page Builder) has one mounted. Installed is not placed. The top-of-list `stock-phone` copy shows on phones and wherever the sidebar copy isn't actually visible (Bespoke's layout hides Flarum's sidebar).
- FoF widgets are opt-in (`isDisabled: !placed()`, admin `registerEditorWidgets`). Bespoke via `BespokeWidgetQueue` with key labels. Page Builder: server block (`Widget\LatestRepliesBlock`, resolve returns nothing) + `app.pageBuilder.registerBlock`, registered in an `app.mount` override after every initializer.
- Realtime only says "ask again" (Posted, Started, revised, renamed, removed, hidden, restored), debounced 1–4 s. Note: flarum/realtime pushes replies on members' own channels only, so guests refresh on tab focus.
- extend.php uses string literals for setting keys. A JS component attribute named `tag` never arrives (`tagSlug`).

## Testing

- `composer test:setup && composer test` (SQLite: `touch` the DB_DATABASE file first or setup fatals and keeps the old driver; and MySQL with `DB_DRIVER=mysql DB_PREFIX=dev_`; check `vendor/flarum/testing/src/integration/tmp/config.php` says mysql), `composer analyse:phpstan`.
- `cd js && npm ci && npm run build && npm run format-check`.
- Local forum `~/Herd/lrdev` (prefix `lr_`); seed, probe (rows per viewer), measure (queries) and puppeteer shots in `~/github/scopes/latest-replies`.
